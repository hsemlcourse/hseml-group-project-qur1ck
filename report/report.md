## 1. Введение и постановка задачи

Решил сделать прогноз среднемесячной температуры Земли по историческим данным. Идея простая: можно ли по температуре за прошлые месяцы предсказать, что будет в следующем.

Задача - регрессия, целевая переменная `LandAverageTemperature`.

Основная метрика - **MAE**, потому что она в градусах и сразу понятно, на сколько модель ошибается. RMSE и R² смотрел дополнительно, но ориентировался на MAE.

---

## 2. Поиск и описание данных

Взял датасет Berkeley Earth с Kaggle - там данные по температуре с 1750 по 2015 год.

- **Строк:** 3 192 (по месяцам)
- **Столбцов:** 9
- **Основные признаки:** дата, средняя температура суши, максимальная/минимальная, температура суши+океана

Данных не очень много, но для начала норм - главное, что длинный период, видно тренды.

## 4. Baseline-модель

В качестве baseline взял обычную линейную регрессию на признаках: `year`, `month`, `temp_lag1`, `temp_lag2`, `temp_lag12`.

Результаты на валидации:

| Метрика | Значение |
|---------|----------|
| MAE | 0.329 °C |
| RMSE | 0.415 °C |
| R² | 0.990 |

Наивный прогноз (просто среднее) даёт MAE 3.8°C, так что модель реально работает.

## 5. Эксперименты

### Эксперимент 1: Сравнение моделей

**Гипотеза:** Может, нелинейные модели дадут прирост.

**Что сделал:** Обучил Random Forest, XGBoost, LightGBM на тех же признаках, сравнил MAE.

**Результат:**

| Модель | MAE (°C) | RMSE (°C) | R² |
|--------|----------|-----------|-----|
| Linear Regression | 0.329 | 0.415 | 0.990 |
| Random Forest | 0.449 | 0.570 | 0.981 |
| XGBoost | 0.447 | - | - |
| LightGBM | 0.418 | - | - |

**Вывод:** Линейная регрессия всё равно лучшая. Видимо, зависимость тут почти линейная, сложные модели только переусложняют.

### Эксперимент 2: Важность признаков

**Гипотеза:** `temp_lag12` (год назад) - самый важный признак.

**Проверка:** Посмотрел на коэффициенты линейной регрессии.

**Что вышло:**
Temperature = -0.435 + 0.0006×year - 0.0095×month + 0.5865×temp_lag1 - 0.3267×temp_lag2 + 0.6531×temp_lag12

`temp_lag12` реально имеет самый большой коэффициент (0.65), потом `temp_lag1` (0.59). `year` почти незаметен (0.0006), но положительный - типа глобальное потепление есть, но слабое.

**Вывод:** Гипотеза подтвердилась.

### Эксперимент 3: Лишние лаги

**Гипотеза:** Добавить `temp_lag3` - станет лучше.

**Проверка:** Сравнил модель с lag3 и без него.

**Результат:** Корреляция lag3 с целевой - 0.012, качество модели не изменилось.

**Вывод:** `temp_lag3` не нужен, можно выкинуть.

## 6. Финальная модель

Оставил **Linear Regression**. Причины:
- Лучшая метрика (MAE 0.33)
- Быстрая, простая, не надо подбирать параметры
- Можно объяснить каждый коэффициент

**Что влияет на прогноз:**
- `temp_lag12` (+0.65) - основной фактор, годовая сезонность
- `temp_lag1` (+0.59) - инерция от прошлого месяца
- `temp_lag2` (-0.33) - корректировка
- `year` (+0.0006) - слабый тренд потепления
- `month` (-0.01) - почти не влияет

## 7. Деплой

Сделал API на FastAPI, один эндпоинт `POST /predict` на порту 8000.

**Пример запроса:**
```json
{
  "year": 2016,
  "month": 1,
  "temp_lag1": 0.5,
  "temp_lag2": 0.3,
  "temp_lag12": 0.8
}
```

**Ответ:**
```json
{
  "predicted_temperature": 1.5718
}
```
